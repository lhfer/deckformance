# 抽象观点的视觉备选

先按 [storyboard.md](storyboard.md) 从页面原文提取 `required`。仅当某个抽象关系仍无法画出来时参考本表；能用真实产品、对象或因果过程直说时，不必强行做隐喻。

| 页面关系 | 可尝试的无字表达 | 常见偏题风险 |
|---|---|---|
| 对比、选型 | 相同条件下的双轨、天平或并排测试 | 只剩“比赛热闹”，看不出比较标准 |
| 结果差异 | 高度/体积/距离不同的同类物体 | 伪造精确数据；需要数值时由 PPT 写 |
| 速度 | 清楚的起点、轨迹和完成位置 | 通用奔跑，与页面对象无关 |
| 安全、可靠 | 被保护对象＋可见防护关系 | 只有盾牌装饰，没有被保护对象 |
| 协作 | 多角色共同完成一件无法单独完成的动作 | 只是同框微笑 |
| 增长 | 同类对象跨阶段变高、展开或扩容 | 无时间/阶段关系的植物摆件 |
| 发布、上线 | 成品从制作状态转为公开可用状态 | 千篇一律剪彩/揭布 |
| 学习、理解 | 混乱结构被角色重新组织成清晰关系 | 只点亮灯泡 |
| 风险、失败 | 明确原因导致阻塞、偏航或失衡 | 只让角色摔倒，原因不明 |

选中方向后仍须回答：谁在做什么、作用于什么、发生在哪里、哪一项视觉证据直接支持 claim。将这些写入 `required` 和 `visualProposition`，再由页面自己的品牌色、角色动作与景别完成构图。

运动不固定为六秒或锁机位。按 [visual-direction.md](visual-direction.md) 选择 `stable`、`cinematic`、`diagrammatic` 或 `ambient`，以观点可读、动作完整和角色稳定为优先。
